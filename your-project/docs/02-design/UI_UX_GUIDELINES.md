# UI/UX Guidelines

- Keep the primary action obvious on every screen.
- Use plain language: “Start mock test,” “Submit answers,” and “View history.”
- Do not hide required actions behind icon-only buttons.
- Ask for confirmation before discarding an active assessment or deleting/deactivating content.
- Show loading feedback while querying the database.
- Provide clear empty states when there are no questions or attempts.
- Preserve form inputs after validation errors.
- Never communicate correctness only with red/green; use labels and icons too.
- Separate practice feedback from final mock-test scoring so the chosen mode feels predictable.
- Avoid surprise navigation or clearing answers when switching screens.
- Use confirmation before submitting a test; list unanswered question count.
- Make errors actionable: “Database connection failed. Check MySQL is running and the settings in your local environment file.”
- Do not display raw SQL, stack traces, password hashes, or database credentials to users.
